# Claude Code vs OpenCode：固定 Token 开销与上下文负担

## 比较对象

- Claude Code
- OpenCode

## 本次观察

- 同类任务中，Claude Code 在读取用户提示前约发送 33k token。
- OpenCode 在相同研究中约发送 7k token。
- 差异说明很多成本并不来自“你让模型做了什么”，而来自“工具先替你塞进去了什么”。

## 为什么这个比较重要

- 固定 token 开销会直接抬高每次任务的基础成本。
- 开销越大，留给真实任务上下文和代码片段的窗口就越少。
- 这类成本通常不容易从产品宣传页看出来，却会强烈影响实际使用体验。

## 这对工具选型意味着什么

- 如果你经常处理短任务，固定开销越高，浪费越明显。
- 如果你经常把长文件、大 diff 或多轮上下文交给代理，壳层越重，可用空间越紧。
- 因此编码代理的评估不应只看模型名，还要看系统提示、工具 schema、缓存策略和上下文注入方式。

## 当前结论

- Claude Code 更像“预装更多能力和控制逻辑，但也更重”的路线。
- OpenCode 更像“壳层更轻、上下文税更低”的路线。
- 这不是最终胜负判断，但足以成为后续评估编码代理时的固定检查项。
