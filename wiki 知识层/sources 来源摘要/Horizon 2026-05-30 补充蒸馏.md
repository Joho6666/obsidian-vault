## 高价值条目

### 1. MCP 并未消亡：社区热议其价值

- 评分：8.8/10
- 来源链接：https://www.quandri.io/engineering-blog/mcp-is-dead
- 一句话摘要：围绕 “MCP is dead” 的争论说明，MCP 的核心价值更像服务发现和生态适配层，而不只是一个传输协议。
- 为什么值得关注：你当前大量关注 Agent、Codex、Claude Code、自动化工作流，MCP 已经是工具接入层的事实标准之一。
- 涉及概念：MCP、服务发现、工具调用、协议生态、上下文窗口
- 涉及实体：Anthropic、OpenAI、modelcontextprotocol
- 与知识库关系：可以补全 `AI Agent / 自动化 / 工作流` 主线中最缺的协议层知识页。
- 建议写入：[[wiki 知识层/concepts 概念页/MCP（模型上下文协议）]]
- 后续行动：后续把你正在使用的 Codex / Claude Code / 本地脚本能力映射到 MCP 可替代或可补充的位置。

### 2. SQLite：足以构建持久化工作流

- 评分：8.6/10
- 来源链接：https://obeli.sk/blog/sqlite-is-all-you-need-for-durable-workflows/
- 一句话摘要：对很多单机或轻量自动化场景，SQLite 可能足以承担持久化工作流引擎的状态存储与恢复职责。
- 为什么值得关注：这直接关系到你做知识库自动化时，是用轻量本地状态机，还是早早引入更重的 Temporal 类系统。
- 涉及概念：持久化工作流、任务恢复、SQLite、Temporal、编排
- 涉及实体：SQLite、Temporal、DBOS
- 与知识库关系：补强 `自动化知识库` 和 `独立开发小工具` 的低成本实现路线。
- 建议写入：[[wiki 知识层/concepts 概念页/SQLite 持久化工作流]]
- 后续行动：后续可以把自动化运行记录、队列状态、失败重试信息设计成 SQLite 版最小实现。

### 3. GPU 规格对比：带宽对本地 LLM 至关重要

- 评分：8.3/10
- 来源链接：https://www.reddit.com/r/LocalLLaMA/comments/1trkze4/i_compared_all_specs_of_the_major_gpusmachines/
- 一句话摘要：本地 LLM 推理时，显存带宽常比名义算力更早成为瓶颈，因此硬件选择不能只看 TFLOPS。
- 为什么值得关注：这能修正“只追最新显卡”的判断方式，帮助你把本地 AI 投资从参数竞赛转向工作负载分析。
- 涉及概念：显存带宽、LLM 推理、VRAM、吞吐、硬件性价比
- 涉及实体：RTX PRO 6000 Blackwell、P100、V100、3090、Mac Studio
- 与知识库关系：和 [[wiki 知识层/concepts 概念页/本地 LLM 部署成本模型]] 直接互补。
- 建议写入：[[wiki 知识层/concepts 概念页/LLM 推理中的显存带宽]]
- 后续行动：把以后关注的显卡、二手卡和工作站统一按 `显存容量 + 带宽 + 功耗 + 价格` 四维比较。
