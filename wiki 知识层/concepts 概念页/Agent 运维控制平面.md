# Agent 运维控制平面

## 定义

当 Agent 不再只是单次实验，而是成批运行、长期运行、跨团队运行时，就需要一个独立的控制层来管理它们。这一层可以理解为面向智能体的 control plane。

## 这次新增认识

- 创建 Agent 的门槛正在下降，真正变难的是部署后的治理。
- 新的问题集中在权限、版本、评估、审计、可观测性、失败恢复和生命周期管理。
- 它与早期容器生态中 “应用易建，集群难管，最终催生 Kubernetes” 的路径相似。
- DRI 不能分配给 Agent 本身，责任归属仍然必须保留在人类 owner 身上。

## 为什么重要

- 多智能体或长期运行 Agent 一旦缺少控制平面，就会迅速出现黑盒化和调试失控。
- 这条线比单纯比较模型更接近可复用的工程能力。
- 它把 Agent 从“demo 工具”推进到“可运营系统”。
- 它也提醒你，自治度提升并不意味着责任可以自动转移给模型。

## 对我的意义

- 你的知识库已经积累了 Agent 记忆、上下文压缩、MCP 和技能安全，这一页补上了生产化治理层。
- 如果后续要让自动化任务更长期、更稳定地跑，控制平面视角会比继续堆 prompt 更有用。
- 在具体工作流里，这意味着每个长期运行的自动化都应该能回答“谁负责”“谁审批”“谁回滚”。
