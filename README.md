# Obsidian Vault 笔记备份

这是从本地 Obsidian Vault 整理导出的 GitHub 备份仓库，用来保存适合版本管理的 Markdown 笔记、知识资料和常用附件。  
该仓库不是完整的 Obsidian 工作区镜像，而是一个经过筛选的、便于长期归档和跨设备查看的笔记版本。

## 仓库用途

- **云端备份**：把重要笔记同步到 GitHub，避免本地硬盘损坏或误删导致资料丢失。
- **版本管理**：通过 Git 记录笔记修改历史，方便回退、对比和追踪整理过程。
- **分类归档**：按知识层、原始资料、AI 工具资料和附件进行拆分，降低后续维护成本。
- **跨设备访问**：在浏览器、GitHub Desktop、VS Code 或 Obsidian 中查看和拉取笔记。

## 目录结构

| 目录 | 内容说明 | 适合放什么 |
| --- | --- | --- |
| `wiki 知识层/` | 已整理、可复用的知识库内容 | 概念页、方法论、总结、教程、对比分析 |
| `raw 原始资料/` | 尚未完全加工的原始材料 | 网页摘录、项目资料、临时调研、采集内容 |
| `ai有关的装备/` | AI 工具与自动化相关资料 | Codex、MCP、Agent、提示词、技能文档、开发流程 |
| `Attachments 附件/` | 笔记引用的常用附件 | 图片、PDF、Canvas、文档素材 |
| `TheSchema.md` | Vault 的结构说明或知识框架 | 分类规则、命名规范、知识体系设计 |

## 推荐使用方式

### 查看笔记

可以直接在 GitHub 页面打开 Markdown 文件查看，也可以克隆到本地后用 Obsidian 打开：

```bash
git clone https://github.com/Joho6666/obsidian-vault.git
```

### 后续同步

建议仍然在本地 Obsidian Vault 中写笔记，然后定期导出或同步到这个仓库。不要直接把完整 Vault 原封不动推送上来，避免把缓存、插件状态、临时文件和隐私内容一起上传。

推荐流程：

1. 在本地 Obsidian 中新增或修改笔记。
2. 将适合归档的内容同步到本仓库对应分类。
3. 检查是否包含隐私信息、账号、Token、Cookie、个人聊天记录等敏感内容。
4. 提交并推送到 GitHub。

## 同步策略

本仓库默认只保留适合 Git 管理的内容：

- 上传 Markdown、图片、PDF、Canvas、文本资料等笔记资产。
- 排除 `.obsidian/` 工作区状态和插件缓存。
- 排除 `.smart-env/`、`.claude/`、`.agents/`、`.codex/` 等 AI/开发工具缓存。
- 排除虚拟环境、依赖目录、安装包、可执行文件和大体积二进制文件。
- 排除可能频繁变化但没有长期价值的临时文件。

## 隐私与安全

当前仓库适合作为**私有备份仓库**使用。  
如果未来要改成公开仓库，必须先做一次完整安全检查：

- 是否包含手机号、邮箱、身份证、住址、学校账号等个人信息。
- 是否包含 API Key、Token、Cookie、密钥、后台密码等凭据。
- 是否包含未公开项目、聊天记录、课程资料或他人资料。
- 是否包含从网页采集但不适合公开传播的内容。

如果发现敏感内容，不能只删除当前文件，还需要清理 Git 历史记录后再公开。

## 维护建议

- 每次同步前先看 `git status`，确认变更范围合理。
- 单次提交尽量只做一类整理，例如“更新 AI 工具笔记”或“补充项目资料”。
- 大文件优先放网盘或对象存储，GitHub 仓库只保留引用说明。
- 定期检查链接、附件引用和重复资料，保持目录可读。

## 当前定位

这是个人知识库的 GitHub 备份版本，重点是稳定、安全、可追溯。  
后续可以继续扩展为更完整的知识库首页，例如增加索引页、标签说明、学习路线和精选笔记入口。
